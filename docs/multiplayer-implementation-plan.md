# 온라인 대전 구현 계획

이 문서는 현재 로컬 2인 턴제 포격 게임을 두 대의 다른 컴퓨터에서 접속해 대전할 수 있는 온라인 게임 구조로 바꾸기 위한 구현 계획입니다.

## 목표

현재 게임은 한 브라우저 안에서 P1과 P2가 번갈아 조작하는 구조입니다. 온라인 대전을 지원하려면 게임 상태의 주인을 클라이언트가 아니라 서버로 옮겨야 합니다.

권장 구조:

```txt
브라우저 A             서버               브라우저 B
Phaser Client  <->  WebSocket Room  <->  Phaser Client
```

서버는 게임 상태를 소유하고, 각 브라우저는 입력을 서버로 보내고 서버가 보내준 상태를 화면에 렌더링합니다.

## 추천 기술 스택

현재 클라이언트 구조는 유지합니다.

- Phaser 3
- TypeScript
- Vite

서버를 추가합니다.

- Node.js
- Express
- Socket.IO
- TypeScript

Socket.IO를 추천하는 이유는 방 관리, 재접속 처리, 이벤트 기반 통신, 브로드캐스트가 편하기 때문입니다. 현재 게임처럼 턴제 기반인 경우 WebSocket을 직접 다루는 것보다 구현 속도와 안정성이 좋습니다.

## 서버가 담당할 것

서버는 다음 상태와 규칙을 관리합니다.

- 방 생성과 입장
- P1/P2 배정
- 현재 턴
- 탱크 위치
- HP, 각도, 파워, MOVE
- 바람
- 지형 파괴 이력
- 포탄 시뮬레이션
- 데미지 계산
- 승패 판정
- 재시작 흐름

## 클라이언트가 담당할 것

클라이언트는 다음 역할을 합니다.

- Phaser 게임 화면 렌더링
- HUD 렌더링
- 내 입력을 서버로 전송
- 내 턴일 때만 조작 허용
- 서버 상태에 따라 포탄과 폭발 애니메이션 재생
- 방 코드, 플레이어 번호, 대기 상태, 상대 턴, 재접속 상태 표시

## 공유 게임 상태

현재 `BattleScene` 안에 있는 게임 상태 타입을 `shared` 모듈로 분리합니다. 이 타입은 클라이언트와 서버가 함께 사용합니다.

예시:

```ts
type GamePhase = "waiting" | "aim" | "flying" | "gameover";

type GameState = {
  roomId: string;
  phase: GamePhase;
  activePlayerId: 0 | 1;
  wind: number;
  players: PlayerState[];
  terrainHoles: TerrainCrater[];
  projectile?: ProjectileState;
};
```

이렇게 분리하면 서버와 클라이언트가 같은 상태 구조를 기준으로 동작할 수 있습니다.

## Socket.IO 이벤트 설계

클라이언트에서 서버로 보내는 이벤트:

```txt
createRoom
joinRoom
playerMove
setAngle
startCharge
releaseShot
setTargetMarker
restartGame
```

서버에서 클라이언트로 보내는 이벤트:

```txt
roomCreated
joinedRoom
stateSync
shotStarted
shotUpdated
exploded
turnChanged
gameOver
errorMessage
```

## 방 생성과 입장 흐름

처음에는 단순한 2인 방 모델로 구현합니다.

1. P1이 방을 생성합니다.
2. 서버가 짧은 방 코드를 반환합니다.
3. P2가 방 코드를 입력해 입장합니다.
4. 서버가 P2를 배정합니다.
5. 두 명이 모두 접속하면 게임을 시작합니다.
6. P1부터 턴을 시작합니다.

이후 확장 기능으로 관전, 비공개 로비, 재대결 투표, 재접속 복구 등을 추가할 수 있습니다.

## 서버 권위 구조

온라인 대전에서는 서버가 최종 판정권을 가져야 합니다.

서버가 반드시 검사해야 하는 것:

- 입력을 보낸 소켓이 현재 턴 플레이어인지
- 현재 게임 단계에서 허용되는 입력인지
- MOVE가 남아 있는지
- 각도와 파워가 허용 범위 안인지
- 발사 가능한 상태인지

클라이언트에서도 내 턴이 아닐 때 조작을 막아 UX를 좋게 만들 수 있지만, 최종 검증은 서버가 해야 합니다.

## 포탄 시뮬레이션

추천 방식은 서버에서 포탄 시뮬레이션을 처리하는 것입니다.

이유:

- 두 플레이어 화면에서 같은 결과가 나옵니다.
- 지형 충돌 결과가 일치합니다.
- 데미지와 승패 판정이 브라우저마다 달라지지 않습니다.
- 치트 방지에도 유리합니다.

흐름:

1. 클라이언트는 스페이스 충전 중 HUD만 로컬로 보여줍니다.
2. 스페이스를 떼는 순간 최종 파워를 서버로 보냅니다.
3. 서버가 파워를 허용 범위로 보정합니다.
4. 서버가 포탄 시뮬레이션을 시작합니다.
5. 서버가 포탄 위치 또는 주요 프레임을 양쪽 클라이언트에 전송합니다.
6. 서버가 지형 충돌을 판정합니다.
7. 서버가 지형 파괴, 탱크 데미지, 턴 전환을 처리합니다.

## 지형 동기화 방식

매 턴 전체 지형 픽셀 데이터를 보내면 너무 무겁습니다.

대신 초기 지형은 같은 방식으로 생성하고, 폭발로 생긴 구멍 정보만 공유합니다.

```ts
type TerrainCrater = {
  x: number;
  y: number;
  radius: number;
};
```

서버는 `terrainHoles` 배열을 저장합니다. 클라이언트는 같은 초기 지형을 만든 뒤 서버가 보낸 구멍 정보를 순서대로 적용합니다.

더 정확한 동기화를 위해 초기 지형은 나중에 `seed` 기반으로 생성하는 것이 좋습니다.

## 리팩터링 순서

1. 공유 상수와 타입을 분리합니다.
2. 지형 관련 헬퍼를 `BattleScene` 밖으로 분리합니다.
3. 포탄 시뮬레이션 로직을 서버에서도 사용할 수 있는 모듈로 분리합니다.
4. 각 단계마다 기존 로컬 게임이 계속 동작하는지 확인합니다.
5. Socket.IO 서버를 추가합니다.
6. 방 생성과 입장 기능을 구현합니다.
7. P1/P2 배정과 대기 UI를 구현합니다.
8. 턴 소유권을 서버로 옮깁니다.
9. 이동과 각도 변경을 서버 이벤트로 전송합니다.
10. 발사 판정을 서버로 옮깁니다.
11. 지형 파괴와 HP 변경을 서버가 브로드캐스트합니다.
12. 게임오버와 재시작을 동기화합니다.
13. 접속 종료와 재접속 처리를 추가합니다.

## 첫 번째 구현 목표

가장 작은 온라인 대전 버전을 먼저 만듭니다.

- 방 만들기
- 방 입장하기
- P1/P2 배정하기
- 초기 상태 동기화하기
- 현재 턴 플레이어만 이동과 조준 가능하게 하기
- 두 브라우저 사이에서 턴 전환 확인하기

이 단계가 끝난 뒤 서버 권위 방식의 포탄 시뮬레이션과 지형 파괴를 구현합니다.

## 메모

이 게임은 턴제 포격 게임이기 때문에 고주파 실시간 넷코드가 필요하지 않습니다. 방 기반 서버 권위 이벤트 모델이 더 단순하고, 안정적이며, 디버깅하기 쉽습니다.
